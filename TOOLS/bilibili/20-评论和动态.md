# 评论和动态

说话的地方：视频评论区、动态。包括看消息、回 @、发/删评论、发/删/转/赞/收藏动态。

> **动态 id 是 19 位数字**，超过 JSON 能精确表示的整数范围。传 `dyn_id` 时原样当**字符串**传（例如 `"1262399430752993300"`），别转成数字——转成数字会掉精度，删/赞/收藏的会变成另一条动态。

---

## 评论区（视频）

### `list_mentions`
| 参数 | 默认 | 说明 |
|---|---|---|
| `limit` | 20 | 最多几条 |
| `kinds` | `"at,reply"` | 逗号分隔，可选 `at` `reply` |

返回**每行一个 JSON**（不是数组），字段：
`kind / rpid / oid / root / parent / from_uid / from_name / text / uri / business_id / at`。

- `rpid` 是对方**这一条**的 id；`parent` 是它直接回复的那条；`root` 是楼层根。
- `at` 消息里，`parent`/`root` 都是它所在的楼层根（B 站 AT 只给 `target_id`）。
- **它不替你查评论内容**。想知道「楼主是谁、说了什么」，拿 `oid` + `root` 去调 `get_comment` 或 `list_thread`（视频）；动态的用 `read_dynamic_comment`。
- `business_id` 是 `1` 就是视频，是 `11` 就是动态。动态那条的 `oid` 不是视频 aid，别拿它去调视频工具。
- 已经按你的态度档过滤过：`forbid` 的类别根本不会出现。已经回过的不会消失，自己看 `at` 判断。

### `get_comment`
| 参数 | 必填 | 说明 |
|---|---|---|
| `oid` | 是 | 视频 aid |
| `rpid` | 是 | 评论 id（楼层根或楼里任意一条都行） |

返回 JSON：`found`、`target`（这条评论：rpid/oid/root/parent/user/mid/content/ctime）、`floor`（楼层根，也就是楼主那条）、`floor_is_target`。
`target.oid` 能直接拿去 `post_reply`；`target.parent` 就是它回复的那条。
只读视频评论；动态的评论用 `read_dynamic_comment`。

### `list_thread`
| 参数 | 必填 | 说明 |
|---|---|---|
| `oid` | 是 | 视频 aid |
| `root` | 是 | 楼层根 rpid |
| `pn` | 否 | 页码，默认 1 |
| `ps` | 否 | 每页条数，默认 20，上限 50 |

返回 JSON：`root`（楼层根 = 楼主）、`replies`（这楼的回复列表）、`page`。
每条回复字段：`rpid/oid/root/parent/user/mid/content/ctime`。
楼中楼想看清顺序，就按 `parent` 串：`parent` 指谁，谁就是它回复的人。
只读视频评论；动态的评论用 `read_dynamic_comment`。

### `post_reply`
| 参数 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 你要说的话，≤ 1000 字 |
| `oid` | 是 | 视频 aid |
| `rpid` | 否 | 对方那条的 id，填了才是"回复他" |
| `root` | 否 | 楼层根，留空就自动用 `rpid` |
| `to_uid` | 否 | 对方 uid，用来记账 |

返回 `{"sent": true, "rpid": …, "toast": "发送成功"}`。
额度用满时会在后面多一段 `【提醒】…`（软限额），或者直接报错（硬限额）。

会被拒绝的情况：主人关了自动回复 / 空内容 / 内容以 `[草稿]` 开头 / 超过 1000 字。

### `comment_video`
在视频底下**开一条自己的评论**（不是回复某个人）。

| 参数 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 你要说的话，≤ 1000 字 |
| `oid` | 二选一 | 视频 aid（`read_video` 返回的第一行就是） |
| `bvid` | 二选一 | 也可以只给 BV 号，工具自己去查 aid |
| `at_master` | 否 | 默认 `true` |

**默认会自动在正文前面加 `@主人 `。** 这是主人的要求：你开口，他要看见。
返回的 `text` 字段是**实际发出去的全文**（含 @），你可以核对。

会被拒绝的情况：主人关了自动回复 / 空内容 / `[草稿]` 开头 / 超过 1000 字 / 没给 oid 或 bvid。

### `delete_comment`
删掉自己在视频底下发的一条评论（主楼、楼中楼都行）。

| 参数 | 必填 | 说明 |
|---|---|---|
| `oid` | 是 | 评论所在视频的 aid |
| `rpid` | 是 | 要删的那条评论 id |

返回 `{"deleted": true, "oid": …, "rpid": …, "raw": {…}}`。
只能删自己的，删别人的 B站 会拒绝。刚发的评论有时要过几分钟才删得掉。

## 动态

### `send_dynamic`
发一条动态。正文自己写，可以带话题、可以 @ 人。

| 参数 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 正文，≤ 2000 字。以 `[草稿]` 开头的会被拒 |
| `topic_id` | 否 | 话题 id，带了就挂这个话题 |
| `at_uids` | 否 | 要 @ 的人的 uid 列表，工具会去查昵称拼成 `@昵称` |

返回 `{"sent": true, "dyn_id": …, "dyn_id_str": "…", "url": "https://t.bilibili.com/…", "at": [...], "topic_id": …, "raw": {…}}`。
- `dyn_id` 记好（原样当字符串记），以后要删这条动态就靠它。
- `url` 是这条动态的网页地址。

发不发、什么时候发、写什么，都是你自己的事。

### `delete_dynamic`
删掉自己的一条动态。

| 参数 | 必填 | 说明 |
|---|---|---|
| `dyn_id` | 是 | `send_dynamic` 返回的那个 id（19 位，原样当字符串传） |

返回 `{"deleted": true, "dyn_id": …, "raw": {…}}`。只能删自己的。

### `comment_dynamic`
回复动态里的评论。`dyn_id` 是动态的 id，`rpid` 是要回复的那条评论的 id。

| 参数 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 评论内容，≤ 1000 字，以 `[草稿]` 开头的会被拒 |
| `dyn_id` | 是 | 动态的 id，动态链接 `/opus/` 后面那串数字（19 位，原样当字符串传） |
| `rpid` | 否 | 要回复的那条评论的 id；不回复某条、直接评论动态就不给 |
| `root` | 否 | 楼中楼的楼层根，一般不用给 |

返回 `{"sent": true, "rpid": …, "dyn_id": …, "oid": …, "comment_type": …, "toast": "发送成功"}`。
- 动态分两种：老动态 `comment_type=17`，新图文（`/opus/` 那种）`comment_type=11`。工具会自己查、自己选对，你不用管。
- 发出去之后评论列表可能要等几秒才刷新出来，别急着当成失败。

### `read_dynamic_comment`
读动态的评论。`get_comment` 和 `list_thread` 只读视频，动态的评论用这个。

| 参数 | 必填 | 说明 |
|---|---|---|
| `dyn_id` | 是 | 动态的 id，动态链接 `/opus/` 后面那串数字（19 位，原样当字符串传） |
| `rpid` | 否 | 要读的那条评论 id |
| `root` | 否 | 楼层根 rpid，给了就读整楼 |
| `pn` | 否 | 页码，默认 1 |
| `ps` | 否 | 每页条数，默认 20，上限 50 |

都不给 `rpid` / `root` 时，返回动态评论区第一页：`page`、`replies`。
给了就返回这栋楼：`root`（楼层根）、`replies`（楼里的回复）、`page`；给 `rpid` 时另有 `found`、`target`（这条评论）、`floor_is_target`。
每条评论字段和 `list_thread` 一样：`rpid/oid/root/parent/user/mid/content/ctime`。
- 动态分两种：老动态 `comment_type=17`，`/opus/` 图文 `comment_type=11`。工具自己查、自己选。
- 返回的 `oid` 是动态的评论 oid，不是视频 aid。

### `list_user_dynamics`
看某个人最近发的动态。

| 参数 | 必填 | 说明 |
|---|---|---|
| `uid` | 是 | 对方 uid |
| `limit` | 否 | 默认 10 |

返回 `动态 id | 作者 | 时间 | 赞 N | 摘要` 一行一条。

### `list_following_dynamics`
关注的人最新动态。`limit` 默认 10。格式和 `list_user_dynamics` 一样。

### `repost_dynamic`
转发一条动态。

| 参数 | 必填 | 说明 |
|---|---|---|
| `dyn_id` | 是 | 要转发的动态 id（19 位，原样当字符串传） |
| `text` | 否 | 转发语，默认「转发动态」 |

返回新动态的 id。

### `like_dynamic`
给动态点赞；`undo: true` 取消。参数 `dyn_id`（19 位，原样当字符串传）、`undo`。

### `favorite_dynamic`
收藏动态；`undo: true` 取消。参数 `dyn_id`（19 位，原样当字符串传）、`undo`。

## 常见活儿

**回一条 @ 或回复**
```
peek_inbox → read_video(oid) → post_reply(text, oid, rpid, root, to_uid)
```
`rpid` / `root` / `to_uid` 全部从任务包的那一项里抄，别自己编。

**想知道「楼主是谁、说了什么」**

```
list_mentions → 拿到 oid/root → get_comment(oid, rpid)   ← 单条：它的 parent、楼层根和楼主
                             → list_thread(oid, root)    ← 整楼：楼主 + 这楼所有回复
```
`at` 和 `reply` 消息的 `root` 都是楼层根，不用猜。`parent` 是它直接回复的那条。

上面是视频。消息里 `business_id` 是 `11`、`uri` 是 `/opus/...` 就是动态，换成：
```
read_dynamic_comment(dyn_id, rpid)   ← 单条
read_dynamic_comment(dyn_id, root)   ← 整楼
```
`dyn_id` 从 `uri` 的 `/opus/<数字>` 里抄。

**回动态下面的评论**
```
comment_dynamic(text, dyn_id)             ← 直接在自己的动态下发一条
comment_dynamic(text, dyn_id, rpid)       ← 回复某一条
```
`dyn_id` 从动态链接 `/opus/<数字>` 里抄，`rpid` 是那条评论的 id。

**发动态 / 删动态**

```
send_dynamic("今天刷到一个视频……")              ← 发出去，返回里有 dyn_id
send_dynamic("……", topic_id=话题id)              ← 挂个话题
send_dynamic("……", at_uids=[uid1, uid2])         ← @ 人
delete_dynamic(dyn_id)                            ← 想删就用这个
```

**转发 / 点赞 / 收藏动态**
```
repost_dynamic(dyn_id, "转发语")     ← 转发
like_dynamic(dyn_id)                 ← 点赞，undo=True 取消
favorite_dynamic(dyn_id)             ← 收藏，undo=True 取消
```

**看某人最近的动态**
```
list_user_dynamics(uid)          ← 他最近发的
list_following_dynamics()        ← 关注的人最近发的
```

**删自己的评论**

```
delete_comment(oid, rpid)               ← rpid 就是当初发评论时返回的那个
```
